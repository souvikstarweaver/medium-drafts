Your Embedding Model Choice Doesn't Matter Until Chunking Strategy Works

Vectara tested 48 embedding models across 25 chunking configs and found chunking had equal or greater impact on retrieval quality.

Most RAG pipelines follow the same playbook. Take documents, split them into chunks, embed those chunks, store the vectors. When retrieval quality falls short, the instinct is to swap the embedding model. Try a larger one. Try a newer one. Spend two weeks benchmarking options.

That instinct is wrong. The bottleneck is upstream, at the splitting step, where most teams never look.

The gap between the best and worst chunking strategy in Chroma's evaluation was 9% in recall Firecrawl Blog — Best Chunking Strategies for RAG 2026. Nine percent. From chunking alone.

This is the wrong variable getting the attention.

The Chunking Problem: Why Most Teams Optimize the Wrong Variable

The default chunking approach in most production RAG systems is fixed-size splitting. Take 512 tokens. Cut. Take another 512 tokens. Cut again. Recursive character splitting is the same idea with mild refinements: it tries to break on paragraph boundaries before falling back to sentence or character boundaries.

Both approaches are blind to meaning. They do not know where a topic ends or begins. They cut sentences in half Milvus/Zilliz Blog, 2025. A paragraph explaining a feature gets split between two chunks, and the embedding for each half represents a fragment, not a concept.

The cost compounds downstream. The embedding model receives a broken input and produces a vector that represents noise. The retrieval system returns this noise. The LLM generates an answer from it.

The Trap of Fixed-Size Chunking

Fixed-size chunking assumes all documents have the same information density. They do not.

On the SQuAD dataset (short, factual paragraphs), 64-token chunks produce the best retrieval recall. On NarrativeQA (long narrative passages), 1024-token chunks win Bhat, Rudat, Spiekermann, Flores-Herr / arXiv:2505.21700, 2025. The optimal chunk size varies by a factor of 16x depending on the content type. No single fixed size works across document types.

Picking 512 as a default is a compromise that optimizes for nothing.

Why Semantic Chunking Inverts the Optimization Pipeline

The standard pipeline is: chunk first, embed second. Fixed-size splitting happens before the embedding model ever sees the text. The embedding model has no say in where boundaries fall.

Max-Min Semantic Chunking reverses that order. It embeds sentences first, then uses the embeddings to decide where chunks should break Milvus/Zilliz Blog, 2025. Think of it like a book editor who reads the full manuscript before deciding where to place chapter breaks, instead of cutting every 20 pages regardless of where scenes end.

The algorithm treats chunking as a constrained clustering problem in embedding space Kiss, Nagy, Szilágyi / Discover Computing (Springer), 2025. It scans sentences left to right, measuring how similar each new sentence is to the current chunk. When a sentence is more different from the chunk than the chunk's internal sentences are from each other, it starts a new chunk.

The result is variable-length chunks where each chunk contains one coherent idea.

The Three Core Hyperparameters

Max-Min requires three settings: a maximum chunk size (the ceiling), a minimum similarity threshold between the first two sentences of a chunk (the floor for starting a new group), and a similarity threshold for adding new sentences to an existing chunk Milvus/Zilliz Blog, 2025.

These thresholds adjust with context as the algorithm scans. The tuning surface is small enough that a team can run a grid search in hours, not weeks.

The Computational Cost is Negligible

The overhead concern is fair but misplaced. Max-Min adds cosine similarity checks while scanning sentences. It does not require an extra model, a multi-stage clustering pipeline, or GPU-heavy processing Milvus/Zilliz Blog, 2025.

In a broader comparison of chunking methods, Max-Min fell into the moderate runtime category and completed processing across all test datasets without timeouts or memory failures arXiv:2606.00881 — Chunking Methods on Retrieval-Augmented Generation, 2026. Several competing methods (including some that scored higher on specific benchmarks) failed to finish on larger datasets. A method that crashes on your corpus is not a method.

The Evidence: Max-Min Outperforms Existing Methods

On clustering quality, Max-Min achieved an Adjusted Mutual Information score of 0.85 and 0.90 on two benchmark datasets. The Llama Semantic Splitter, the closest competitor, scored 0.68 and 0.70 on the same tests. On downstream question-answering accuracy, Max-Min reached 0.56 compared to Llama's 0.53, and the improvements were consistent across evaluation runs Kiss, Nagy, Szilágyi / Discover Computing (Springer), 2025.

The clustering gap is the number that matters most. AMI measures how well chunk boundaries align with actual topic boundaries in the source document. A score of 0.85 means Max-Min's boundary detection agrees with human-labeled topic boundaries 85% of the time. The Llama splitter's 0.68 means it misses about a third.

Bhat et al.'s work on chunk-size sensitivity reinforces the case for adaptive chunking: SQuAD Recall@1 hit 64.1% at 64 tokens, while NarrativeQA Recall@1 reached 10.7% at 1024 tokens Bhat et al. / Semantic Scholar, 2025. Any fixed chunk size leaves performance on the table for at least one document type. Max-Min's variable sizing addresses this by design.

The Blind Spot: Context Fragmentation and Local-Only Clustering

Max-Min solves boundary detection. It does not solve long-range semantic dependencies.

The algorithm clusters sentences by scanning left to right and comparing each new sentence to the current chunk. It cannot see relationships that span multiple chunks Milvus/Zilliz Blog, 2025.

A concrete example: take release notes for Milvus 2.4.13. The version identifier appears in one chunk. The list of new features appears in another. A user query asking "What new features shipped in 2.4.13?" fails because the embedding model cannot connect the version number chunk to the feature list chunk. The version number and features are semantically related, but they were split because the sentences between them were about different topics.

This fragmentation affects both retrieval and generation. Even if retrieval surfaces the feature list chunk, the LLM receives it without the version context and cannot confirm which release it belongs to.

Why Independent Benchmarks Show Mixed Results

The Kiss et al. results are strong, but they are not the full picture. A 2026 survey of chunking methods found Max-Min underperforming GraphSeg, Recursive Semantic, and DenseX on some end-to-end generation tasks arXiv:2606.00881 — Chunking Methods on Retrieval-Augmented Generation, 2026.

The discrepancy is explained by what each benchmark measures. Kiss et al. tested clustering quality (how well chunks map to topic boundaries) and single-hop QA. The 2026 survey tested end-to-end generation quality, where the LLM's ability to synthesize across multiple retrieved chunks matters as much as retrieval precision.

The survey also noted that many top-performing methods failed due to timeouts or memory issues on larger datasets. Max-Min completed processing on every dataset. For production systems where reliability is a constraint, not a luxury, consistency of completion matters as much as peak accuracy on a favorable benchmark.

The Retrieval-to-Answer Accuracy Cliff

The sharpest tension in semantic chunking is the gap between retrieval recall and end-to-end answer accuracy.

Semantic chunking achieved 91.9% retrieval recall in one evaluation AI Agents Buzz — RAG Chunking Strategies Visual Guide 2026. The retrieval system found the right chunks. But end-to-end answer accuracy landed at 54%. The LLM got the right inputs and produced the wrong outputs nearly half the time.

The cause: unconstrained semantic chunking produced fragments averaging 43 tokens. These fragments were precise enough for the retrieval model to match, but too small for the LLM to reason over. Recursive 512-token splitting achieved 69% answer accuracy on the same evaluation because the LLM received enough surrounding context to construct a coherent answer Firecrawl Blog — Best Chunking Strategies for RAG 2026.

High retrieval recall with low answer accuracy is worse than moderate retrieval recall with high answer accuracy. The user does not see recall numbers. The user sees the answer.

How to Adopt Max-Min Without the Blind Spots

Three rules close the gaps.

Enforce a minimum chunk size floor. Max-Min's dynamic thresholds can produce fragments small enough to win retrieval benchmarks but too small for the LLM to use. Setting a minimum of 150 tokens prevents the 43-token fragment problem that collapses answer accuracy.

Apply context recovery for long-range dependencies. Sliding windows and overlapping chunk boundaries give the retrieval system access to sentences from adjacent chunks Milvus/Zilliz Blog, 2025. Multi-pass scans can re-cluster chunks at a higher level, grouping related chunks that share cross-references like version numbers and feature lists.

Match Max-Min to the right document types. The algorithm works best on structured technical documents: API references, product specs, server logs, release notes, troubleshooting guides Milvus/Zilliz Blog, 2025. These documents have clear local topic boundaries and limited long-range dependencies. For legal contracts, academic papers, or narrative documents with dense cross-references, a hybrid approach combining Max-Min with a global re-clustering pass will outperform Max-Min alone.

| What Max-Min Solves | What Max-Min Does Not Solve | |---|---| | Arbitrary token-based cuts that split mid-sentence | Long-range semantic dependencies across sections | | Unrelated ideas grouped into the same chunk | Version identifiers separated from feature lists | | Fragmentation of coherent concepts within single chunks | Terminology defined in section 1, used in section 7 | | One-size-fits-all chunk sizing across document types | Cross-document references and entity resolution |

Max-Min's scope: It fixes boundary detection in embedding space but requires hybrid strategies for long-range context recovery.

Conclusion

The Vectara data makes the priority clear: chunking configuration has as much or more influence on retrieval quality than embedding model choice Vectara / NAACL 2025 — arXiv:2410.13070 — via PremAI Blog, 2025. Every week spent benchmarking embedding models while using default 512-token splits is a week spent optimizing the smaller lever.

Max-Min Semantic Chunking is not a complete solution. It is the correct first optimization for any team running a RAG pipeline on structured technical content. Fix the boundaries, enforce a size floor, add context recovery where the documents demand it. Then, and only then, benchmark your embedding model.
